## obs#1 — Header de la hoja = franja N3 full-bleed (no PageHeader flotante)

**Defecto:** `NuevaCitaView.tsx:327` usa el átomo genérico `PageHeader` (flotante, redondeado, in-body) dentro de `FormPageScaffold`. El mockup (línea 61) dibuja una **franja N3 full-bleed sticky** (`bg-card` + `border-bottom` + sticky + radius:0) "espeja EntitySubNavBar canon".

**Fix:** swap `PageHeader` → **`EntitySubNavBar`** (`@luana/ui-kit`) en workspace-mode, espejando el hermano `adrian/embudo/nuevo` (`NewLeadPage.tsx:111`):
```tsx
<EntitySubNavBar
  rootHref={`/${tenantId}/mateo/agenda`}
  rootLabel="Agenda"
  entity={{ id: "nueva-cita", name: "Nueva cita" }}
  leaves={[]}
  activeLeaf={null}
/>
```
- Quitar el `PageHeader` + `header={...}` de `FormPageScaffold` (o pasar el EntitySubNavBar como header si el scaffold lo soporta full-bleed; si no, sacar el header del scaffold y montarlo arriba como hace NewLeadPage). El back-nav lo da `rootHref` (link determinístico a /mateo/agenda) — se puede quitar `handleBack`/`router.back()`.
- **Reconciliación (obs#3):** el átomo propuesto "PageHeader back-pill" del mockup es **redundante** con EntitySubNavBar workspace-mode → NO promover, NO crear. EntitySubNavBar es el header-leaf canon (el sibling lo prueba).

**Test:** render → el header es sticky full-bleed (no card redondeada) + `‹ Agenda` navega a `/{tid}/mateo/agenda` + título "Nueva cita". Reusar el patrón de test de `NewLeadPage`/`EntitySubNavBar`.

## obs#3 — Galería de estados: 4 chips distintos + guía contextual por bloqueo

**Defecto:** `AvailabilityChip.tsx:133` mapea `available→success` y **busy + out_of_hours + no_schedule TODOS → `warning`** (mismo ámbar, indistinguibles). Falta guía accionable por estado (solo `FreeDoctorsList` para busy).

**Fix:**
- **D3a · status→variant distinto** (las variants ya existen en kit `badge.tsx`):
  - `available` → `success` · "✓ Médico disponible"
  - `busy` → `destructive` · "✕ Ocupado — se solapa con HH:MM" (RN-1)
  - `out_of_hours` → `warning` · "✕ Fuera del horario" (RN-3)
  - `no_schedule` → `secondary` · "○ Sin horario registrado" (RN-4)
- **D3b · Guía contextual por bloqueo** (Alert atom, copy del mockup, Spanish neutro):
  - `out_of_hours` → Alert warning: "Elige una hora dentro del horario de atención, o reasigna a otro médico que atienda más temprano."
  - `no_schedule` → Alert info: "Carga el horario de este médico primero en Mi Clínica › Horarios."
  - `busy` → mantener `FreeDoctorsList` ("Médicos disponibles a esta hora" + reasignar 1-clic, ya existe).
- **D3c · verificar** que `DayAvailabilityStrip` renderiza las variantes de bloqueo (colisión roja / fuera-de-banda / vacío "Sin horario"), no solo el happy.
- **409 toast** "Ese horario acaba de ocuparse" — ya cubierto por integration test; ejercer live en el cierre del loop.
