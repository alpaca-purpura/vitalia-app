**RN-3 (In-horario validation):** Pre-insert check in create_appointment → if outside doctor's `availability_block`, return 422 OUT_OF_HOURS. Advisory chip on FE (`SC-fuera-horario`). Server-side guarantee: POST direct that bypasses UI rejected (SC-bypass-availability).

**RN-5 (Duración del servicio):** Service DTO carries `initial_appt_duration_minutes`. NULL → FE defaults 30 (editable). Fin = inicio + duración (override > inicio, validated RN-5). Works with auto-select from dropdown.

**RN-9 (Dedup paciente por teléfono):** Inline create checks `find_by_phone`. Existing → prompt "¿usar ese?". Guard PHI duplication from day-1. Optional if FOLD'd late, but FOLD'd (D-C) for data quality.

**RN-10 (Disponibilidad advisory, server-side guarantee):** Chip shows status (AVAILABLE|BUSY|OUT_OF_HOURS|NO_SCHEDULE). Crear blocked if not AVAILABLE (fail-closed RN-10). Server still enforces: EXCLUDE (solape) + pre-insert check (horario) = guarantees. Endpoint down → chip shows "No pudimos verificar, reintentá" + disable Crear.

## 14. Free-form notes — what I'd tell a smart colleague

**Critical path:** T-BE-2 (migration EXCLUDE) must pass before T-BE-3 (availability endpoint).
