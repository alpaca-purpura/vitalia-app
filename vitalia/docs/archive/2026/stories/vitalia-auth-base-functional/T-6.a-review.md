## Findings

### WARN: assertion-swallowing `.catch(() => {})` pattern

**Category:** 10 (Tests/TDD) — weakens test signal
**Files:**
- `vitalia/frontend/e2e/auth/sign-in-redirect.spec.ts:62-64` (3 occurrences in test "SC-02")
- `vitalia/frontend/e2e/auth/sign-in-form.spec.ts:29, 45, 59, 74` (4 occurrences across SC-03 + SC-04)
- `vitalia/frontend/e2e/admin/tenants-users.spec.ts:42, 49, 68-69, 78, 90, 113-114, 125, 135, 150-151` (10+ occurrences)

**Issue:** `await expect(X).not.toBeVisible(...).catch(() => {});` — when `expect` rejects (assertion fails), `.catch` swallows the failure silently. Test passes regardless of whether the element IS visible. This is a Playwright anti-pattern per `playwright-expert/references/anti-patterns.md`: assertion expressions MUST NOT be wrapped in `.catch()`.

Example offending block (sign-in-form.spec.ts:28-29):
```typescript
const placeholder = page.getByText(/pendiente.*T-fe-3/i);
await expect(placeholder).not.toBeVisible({ timeout: 5_000 }).catch(() => {});
```
If "pendiente T-fe-3" text IS visible on the page, this assertion will reject — but `.catch(() => {})` swallows the rejection → test passes incorrectly.

**Impact:** Multiple SC-03 / SC-04 negative assertions (no placeholder text) become **no-op**. If T-2 had failed to delete placeholders, this spec would still pass. Defeats purpose of the assertion.

**Fix:** Remove `.catch(() => {})` from all `expect` calls. Use Playwright's built-in `.not.toBeVisible()` which already supports timeout natively. Where the locator may genuinely not match (e.g., element optionally present), use `locator.count()` pattern or `isVisible()` (returns boolean, no throw):

```typescript
// Wrong (current):
await expect(placeholder).not.toBeVisible({ timeout: 5_000 }).catch(() => {});

// Right:
await expect(placeholder).toHaveCount(0, { timeout: 5_000 });
// or, if optional presence:
const isPresent = await placeholder.isVisible({ timeout: 5_000 }).catch(() => false);
expect(isPresent).toBe(false);
```

Some `.catch(() => false)` usages on `isVisible()` ARE legitimate (per Playwright docs `isVisible` returns boolean — but with timeout option Playwright wraps and may reject). Distinguish:
- `expect(...).catch(() => {})` → **always wrong** (swallows assertion)
- `locator.isVisible(...).catch(() => false)` → acceptable boolean coercion pattern (line 42 admin spec, line 43 mobile)
- `page.waitForLoadState("networkidle", { timeout }).catch(() => {})` → acceptable since networkidle is best-effort

**Skill ref:** `playwright-expert/references/anti-patterns.md` (assertion-swallowing). `e2e-testing.md` indirect.

### WARN: dashboard test mocks `/api/v1/vitalia/tenant/profile` but Server fetches `/api/v1/iam/me`

**Category:** 10 (Tests/TDD) — divergence Server fetch endpoint vs e2e mock
**File:** `vitalia/frontend/e2e/dashboard/welcome.spec.ts:29` (`page.route("**/api/v1/vitalia/tenant/profile", ...)`)
**Issue:** T-3 DashboardWelcome Server Component fetches `${backendUrl}/api/v1/iam/me` (line 29 of DashboardWelcome.tsx). The e2e mock intercepts a DIFFERENT route `**/api/v1/vitalia/tenant/profile`. The mock won't be hit → fetch goes to real backend or returns the fallback shape (line 64-80 of DashboardWelcome.tsx).

Since DashboardWelcome has a try/catch fallback to safe defaults, the test may still pass via the fallback path — but it's not testing what it claims to test (real backend fetch shape). The mock declarations for `/api/v1/vitalia/dashboard/summary` + `/api/v1/vitalia/wizard/status` (lines 49, 68) are similarly orphan — those routes are not consumed by current T-3 component.

**Fix:** Update mock route to `**/api/v1/iam/me` matching the actual fetch in DashboardWelcome.tsx, OR delete the unused mocks. Better: align mock to source-of-truth fetch path.

```typescript
// Replace lines 29-46 mock with:
await page.route("**/api/v1/iam/me", async (route) => {
  if (route.request().method() !== "GET") return route.continue();
  await route.fulfill({
    status: 200,
    contentType: "application/json",
    body: JSON.stringify({
      userId: "user_test",
      firstName: "Demo",
      lastName: "User",
      email: "demo@test.com",
      role: "admin_clinic",
      isOnboarded: false,
      clinicName: "Clínica Vitalia Demo",
      planTier: "starter",
      tenantId: "vitalia-test-tenant",
      clinicId: "clinic_001",
    }),
  });
});
```
