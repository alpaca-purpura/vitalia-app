## 14. Free-form notes — what I'd tell a smart colleague

**This is the **corazón** of Fase 2.** Everything hinges on cobrar saldo subform working end-to-end without leaving the flow. Minute you make the user open a separate modal or navigate away, the UX crumbles. Inline is non-negotiable.

**Biggest gotchas:**

1. **Service-blocker is REAL.** Both `vitalia-payment-adapter-mvp` and `vitalia-fiscal-emission-pe` are `refined`/`refining`, not shipped. Architect documented Option A (stubs + MSW) to unblock parallel work. DO NOT wait. Stubs are production-safe (marked DEPRECATED, tests mock). When the real adapters ship, swapping in is one-line endpoint change per port impl.

2. **HIPAA-lite dual filter is NOT optional.** Every single query touching Appointment or Patient must have `clinic_id` checked. The arch test `test_phi_dual_filter.py` will catch you if you forget. EVERY endpoint. No exceptions.

3. **Slot DTOs are projected server-side.** Frontend NEVER receives raw `patient.name` or `appointment.diagnosis`. The DTO masking happens in `AgendaSlotService`, and the response_model enforces it. This is where the HIPAA-lite mandate lives. Frontend can't undo masking, so the server has sole authority.

4. **Audit log sync-write is defensive.** If you make it async fire-forget, compliance fails. Regulatory requirement: every read of PHI must be logged, and the log write must complete before you return the response. The AsyncAuditWriter handles this transactionally within the same session.

5. **Charge saga has NO rollback.** If payment succeeds but fiscal emit fails, you don't revert the payment. Compensation pattern: you retry the emit standalone, and the user gets a retry button + success toast even if emit hangs. This is intentional per architect A6. Don't fight it.

6. **Playwright visual goldens are the source of truth.** Chris ratified 10 HTML mockups per story. Your components must match those snapshots (0.1% tolerance via maxDiffPixelRatio). If you deviate—color, spacing, button text—you're re-opening a design conversation. Build to the mockup, not your intuition.

7. **Virtualization with react-window.** Calendar month view with 30+ days each with 10-20 slots = 300+ cells. Performance will drop unless you virtualize. The architect decided: server aggregates metrics per month, FE renders virtualized grid. Do NOT skip this. Tests will spot lag.

8. **Idempotency keys are client-generated UUIDs.** User clicks "Cobrar" → generates UUID locally → includes in POST `/api/v1/payments/charge`. Server stores as external_idempotency_key. If the request times out and user retries, same UUID prevents duplicate charge. This is non-negotiable for financial transactions.

9. **i18n/l10n currency is tricky.** Tenant locale defaults to currency (AR = ARS, PE = PEN, MX = MXN). But APPOINTMENTS can override (clinic in Argentina serving tourists in USD). The DTO must include `currency_override: str | None`. Frontend formatting uses tenant default UNLESS override present. Read .claude/rules/currency-handling.md carefully.

10. **Architect's one-shot full-stack design is TIGHT.** Zero ambiguity in 03-arch. Every component gets a decision tree + test path. If the spec says "resize draggable 440-640px", it's tested. If it says "dark mode", goldens cover both. Follow the spec verbatim. Architect did the hard work; your job is execution, not re-design.
