**States visual:** idle/loading (skeleton) · success (doctor vs recepcion PHI masking) · empty (0 convs / filter no-match) · error (fetch fail → banner + retry) · agent-thinking (typing indicator) · agent-waiting-approval (✨ banner + [Approve][Edit][Discard]) · agent-failed (🔴 banner + auto-switch manual) · full (Valeria collapsed).

**Accessibility:** tab order (search → filters → conv → mode toggle → composer); aria-current (conv) + aria-selected (mode); Esc in composer → focus thread; axe wcag2aa pass.

## 14. Free-form notes — what I'd tell a smart colleague

This is a **consolidation story masquerading as a feature**, which changes the risk profile entirely. The inbox is already shipped, tested, and in production (`vitalia/frontend/src/features/inbox/` ~40 components). The real work is (1) moving it from the orphaned location into the shell-organism paradigm, (2) un-stubbing `ComplianceService` (1 method swap in DI), and (3) adding nudge (1 service + 1 endpoint). That's it.

**Key gotchas:**
- **Don't reinvent the wrapper:** The shell-organism (splitter, Valeria sidebar, Ribbon, SubTabsBar) is rock solid and ratified by Chris multiple times. Resist the urge to "simplify" the layout or move the Valeria state around. `useShellStore` is the SSoT for that. The mode-conversaation button just remembers the prior state in the inbox-store locally.
- **Two sets can't coexist:** `features/inbox/` and `features/adrian/components/inbox/` are both active before consolidation. T-4 must DELETE the huérfano in the same PR that migrates. The gate `av-no-orphan-inbox` validates `features/inbox/` no longer exists post-merge. This is a hard lesson from [[recovered-WIP-Story-12]] and [[machinery-hardening-2026-05-28]].
- **Compliance is a stub:** The `_NoOpComplianceService` in `vitalia/backend/src/modules/vitalia/inbox/api/router.py:150` is a placeholder. T-1 wires the real `ComplianceService` from `core/luana-core-compliance/`. The gate is per-channel: WhatsApp free tier rejects PHI (clinical data), others allow it. The RN-7 / SC-3 test is the proof that this gate works (e2e sends a query about results → Adrián does NOT respond with clinical data; instead redirects to portal).
- **DoD #37 is live-verify, not mocked:** This story touches UI that users interact with (Adrián Inbox is a daily tool). The bar is not "all tests GREEN" (though that's baseline). The bar is "I exercise the inbox in real dev-app, 3-modos work, nudge works, Valeria collapses, PHI firewall blocks correctly, and I see the effect in the database and in the Chrome console (zero errors)." Playwright e2e is the regression guard, but Chris's eyes on live dev-app are the final gate. Don't skip that.
- **Polling, not realtime:** The MVP uses polling (list 10s, activity-stream 5s). Don't architect for WebSocket; the story explicitly defers that. A future story will add BroadcastChannel when needed.
- **No engine edit:** Sales agent runtime, copilot trace, compliance engine are all off-limits. If a tool needs tweaking or a prompt needs a slight reword, escalate to /pm-vitalia (not a ticket). T-2 NudgeService resolves the tool via DI (service resolver pattern), never imports it directly.
